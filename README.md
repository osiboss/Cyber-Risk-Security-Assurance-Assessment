# Cybersecurity Risk Assessment & Security Assurance

## Project Overview

I completed a cybersecurity risk assessment and security control review for a fictional UK-based financial services organisation, using the **NIST Cybersecurity Framework (CSF) 2.0** as the assessment framework.

The purpose of the assessment was to identify key cybersecurity risks, assess their potential impact, review existing security controls, identify control gaps and develop practical remediation actions.

The project was designed to demonstrate how cybersecurity risk can be assessed from both a technical and business perspective, rather than focusing only on individual security incidents.

---

## Organisation Scenario

**Northbridge Financial Services Ltd** is a fictional organisation created for this portfolio project.

The organisation represents a UK-based financial services company with approximately 250 employees and a hybrid cloud environment.

The scenario includes:

- Microsoft 365
- Microsoft Azure
- Windows 11 corporate endpoints
- Azure-hosted applications
- Customer-facing web applications
- Internal business applications
- Remote workers and remote access
- Third-party suppliers
- Cloud-based data storage

The assessment assumes that the organisation handles customer, financial and employee information and relies on cloud services and third-party providers for parts of its operations.

The assessment considered the security of key business assets, processes and technologies, including:

## Assessment Methodology

The assessment followed a structured risk and security assurance process:

1. Defined the organisation and assessment scope
2. Identified key assets and business processes
3. Identified relevant cybersecurity threats and risks
4. Assessed likelihood and potential business impact
5. Calculated and prioritised risk
6. Reviewed existing security controls
7. Identified control gaps
8. Considered the relevant NIST CSF 2.0 Functions
9. Developed risk treatment and remediation actions
10. Documented the results in a security assurance report

---

## Risk Assessment

A 5x5 likelihood and impact model was used to assess each identified risk.

**Risk Score = Likelihood × Impact**

The scoring model used the following ratings:

| Score | Rating |
|---|---|
| 1–4 | Low |
| 5–9 | Medium |
| 10–15 | High |
| 16–25 | Critical |

The assessment identified:

- **2 Critical risks**
- **8 High risks**
- **10 remediation actions**

The risks assessed included:

- Phishing and employee credential compromise
- Excessive user privileges
- Azure misconfiguration
- Ransomware
- Unpatched vulnerabilities
- Third-party supplier compromise
- Sensitive customer data exposure
- Weak incident response processes
- Loss of critical cloud services
- Privileged account compromise

---

## Security Control Assessment

Existing security controls were reviewed against the six NIST CSF 2.0 Functions:

- **Govern**
- **Identify**
- **Protect**
- **Detect**
- **Respond**
- **Recover**

The review considered the current state of each control, existing security practices, the risks addressed, identified gaps and potential improvements.

The assessment did not assume that controls were either completely effective or completely absent. Where appropriate, controls were recorded as **Partially Implemented** where further monitoring, testing, documentation or improvement was required.

This provided a more realistic view of security maturity within the fictional environment.

---

## Key Control Gaps

Several areas were identified where existing controls could be strengthened.

Examples included:

- Inconsistent MFA coverage and the need for stronger authentication for higher-risk accounts
- Limited consistency in vulnerability remediation tracking
- Access reviews not being performed regularly enough for sensitive systems
- Further monitoring required for Azure configuration
- Additional validation of backup and recovery arrangements
- Limited ongoing security assurance of third-party suppliers
- Opportunities to strengthen data access monitoring and DLP controls
- Incident response procedures requiring regular testing
- Further validation of recovery objectives and business continuity arrangements
- Opportunities to strengthen privileged access management

---

## Risk Treatment & Remediation

Each identified risk was linked to a practical remediation action.

Examples included:

- Expanding MFA coverage and introducing phishing-resistant authentication
- Establishing vulnerability remediation SLAs
- Introducing scheduled access reviews
- Improving Azure configuration monitoring
- Strengthening endpoint security and ransomware protection
- Performing regular backup and recovery testing
- Improving third-party security assurance
- Strengthening data access monitoring and DLP
- Conducting incident response exercises
- Strengthening privileged access management

This created a clear relationship between:

**Risk → Control Gap → Recommended Action → Risk Treatment**

---

## Key Findings

The assessment identified identity and access management, vulnerability management, cloud security, third-party risk, data protection and recovery capabilities as areas requiring continued attention.

The highest-scoring risks were prioritised for remediation based on their assessed likelihood and potential business impact.

The assessment also highlighted that having a security control in place does not necessarily mean that the control is fully effective. Regular testing, monitoring, evidence collection and review are important parts of ongoing security assurance.

## Conclusion

The assessment provided a structured view of the organisation's cybersecurity risk exposure and demonstrated how identified risks can be connected to existing security controls, control gaps and practical remediation actions.

The review identified several areas where controls were already in place, while also highlighting areas requiring further monitoring, testing, documentation or improvement.

The resulting remediation plan provides a practical set of actions that could be used to address the identified control gaps and reduce exposure to the highest-priority risks.

This project demonstrates my ability to approach cybersecurity from a **risk, control and security assurance perspective**, while considering both technical security requirements and their potential business impact.
